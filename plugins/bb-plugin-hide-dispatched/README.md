# bb-plugin-hide-dispatched

Плагин для **BB**, который автоматически прячет из сайдбара служебные треды —
любой **тред с родителем** и треды от отслеживаемых плагинов (`bb tasks
dispatch`) — переводя их в `visibility: "hidden"`.

## Зачем

BB наследует дочернему треду видимость родителя: у видимого координатора все
помощники и исполнители лезут в корень сайдбара, кто бы их ни создал — команда
плагина, `bb thread spawn --parent-*`, `bb tasks dispatch` или SDK другого
плагина. Встроенной настройки для этого нет. Скрытый тред остаётся живым и
полностью отслеживается панелью Tasks — её статусы идут через события `thread.*`
и `threads.get` по прямому ID.

## Что скрывается

1. **Тред с родителем** (`parentThreadId` не пуст) — всегда. Исключение —
   **форк** (`originKind = "fork"`): его делает человек из интерфейса. Скрывать
   и форки — настройка `hideForks` (по умолчанию `false`).
2. **Тред от отслеживаемого плагина** (`originPluginId` из списка `tracked`,
   по умолчанию `["tasks"]`).
3. **Тред без родителя** из CLI или окна — **не скрывается**: это может быть
   тред человека, а отличить агента от человека по данным BB нельзя.

## Когда

- `thread.created` — сразу при создании.
- `experimental_thread.parentChanged` — родителя назначили после создания
  (`bb thread update --parent-thread`).
- `thread.active` — запасной путь для сервера/SDK без `parentChanged` и повтор
  после ошибки `threads.update`.
- **Уже скрытый тред** (например, создан с `visibility: hidden`) плагин не
  трогает API, но записывает в множество — иначе после ручного «показать в
  сайдбаре» он скрыл бы тред обратно.
- **Не больше одного скрытия на тред.** Запоминаются только обработанные треды
  (kv-множество id с обрезкой записей старше 30 дней). Нескрытый тред
  проверяется на каждом событии заново; если человек вернул видимость —
  плагин его больше не трогает.
- Ошибки `threads.update` логируются, не роняя создание тредов; повтор — на
  следующем `thread.active`, не чаще одного раза на событие.

## Настройки

`bb plugin config hide-dispatched`:

| Ключ | По умолчанию | Действие |
|---|---|---|
| `hideChildren` | `true` | Скрывать любой тред с родителем. `false` — поведение r1 (только `tracked`). |
| `hideForks` | `false` | Скрывать и форки (`originKind = "fork"`). |

## CLI-команда `bb hide-dispatched`

```
bb hide-dispatched status              # включён ли плагин, обе настройки,
                                       # отслеживаемые originPluginId, счётчик
bb hide-dispatched on                  # включить скрытие
bb hide-dispatched off                 # выключить скрытие
bb hide-dispatched sweep               # разовая уборка: скрыть видимые неархивные
                                       # треды по правилам выше
bb hide-dispatched sweep --dry-run     # только показать кандидатов, ничего не менять
```

Все подкоманды поддерживают `--json` для машиночитаемого вывода.

Состояние (включён/выключен, список отслеживаемых, множество обработанных id,
счётчик) хранится в `bb.storage.kv` и переживает перезапуск. По умолчанию
скрытие включено.

## Установка

```bash
bb plugin install /path/to/plugins/bb-plugin-hide-dispatched
```

## Сборка и проверка

```bash
npm install
npm run typecheck   # tsc --noEmit, без ошибок
npm test            # node --test, тесты спеки §4 с поддельным SDK
```
