# hide-dispatched

Плагин скрывает из сайдбара служебные треды (`visibility: hidden`). Работает независимо от orchestrator — и в тредах «Без плагина» (orchestrator §19.3).

## 1. Что скрывается

1. **Тред с родителем** (`parentThreadId` не пуст) — всегда, кто бы его ни создал: команда плагина, `bb thread spawn --parent-*`, `bb tasks dispatch`, SDK другого плагина. Причина: BB наследует дочернему треду видимость родителя, у видимого координатора дочерний тред видим (факт SDK 0.6.x: «a child inherits its parent»). **Исключение — форк** (`originKind = fork`): его делает человек из интерфейса, по той же причине, по которой не скрываются корневые CLI-треды. Хочется скрывать и форки — настройка `hideForks` (`false` по умолчанию).
2. **Тред от отслеживаемого плагина** (`originPluginId` из списка `tracked`, по умолчанию `["tasks"]`) — как в r1.
3. **Тред без родителя, созданный из CLI или окна, — не скрывается:** это может быть тред человека. Отличить агента от человека по данным BB нельзя (`origin = cli`, `senderThreadId = null` у обоих, факт 15.11). Если проба orchestrator PLUG-266 покажет, что у запуска из треда агента `senderThreadId` не пуст, — такой тред скрывается (правило дописывается по итогу пробы).

## 2. Когда

- Событие `thread.created` — сразу.
- Событие `experimental_thread.parentChanged` (SDK 0.6.132) — родителя назначили после создания (`bb thread update --parent-thread`). Сервер или SDK без события — запасной путь: проверка на `thread.active`.
- **Уже скрытый тред** (например, создан с `visibility: hidden` командой orchestrator) плагин не трогает API, но записывает в то же множество — иначе после ручного «показать в сайдбаре» он скрыл бы тред обратно.
- **Не больше одного скрытия на тред:** запоминаются только треды, которые плагин **скрыл** (`kv`, множество id с обрезкой старше 30 дней). Нескрытый тред проверяется на каждом событии заново; если человек сделал скрытый плагином тред видимым — плагин его больше не трогает.
- Ошибка `threads.update` — в журнал, создание треда не ломается; повтор — на следующем `thread.active`, не чаще одного раза.

## 3. Настройки и CLI

- `hideChildren` — `true` по умолчанию; `false` возвращает поведение r1 (только `tracked`).
- `hideForks` — `false` по умолчанию (§1 п.1).
- `bb hide-dispatched status|on|off` — как в r1; `status` показывает и `hideChildren`.
- `bb hide-dispatched sweep [--dry-run]` — скрывает видимые неархивные треды по правилам §1 (с родителем или от `tracked`), уже скрытые плагином по §2 не трогает.

## 4. Тесты

Поддельный SDK: тред с родителем от `cli`/`sdk`/`plugin` → скрыт; без родителя от `cli`/`app` → не тронут; родитель назначен позже → скрыт по `parentChanged`, без события — на `thread.active`; тред не скрыт на создании (родителя нет) → скрыт позже, а не «рассмотрен навсегда»; форк → не тронут, `hideForks = true` → скрыт; человек открыл тред → второй раз не скрывается; тред создан уже скрытым → записан, после ручного показа не скрывается; `hideChildren = false` → только `tracked`; ошибка `update` → журнал, без исключения наружу.
